# تشغيل «مدقّق مالي» على خادم منزلي (جهاز آخر)

دليل عملي لتثبيت النظام وتشغيله على خادمك الخاص، والوصول إليه من أجهزة أخرى في الشبكة.

يوجد مساران:

- **المسار (أ) — إنتاجي (موصى للخادم):** بناء مُحسَّن + دورين لقاعدة البيانات مع تفعيل عزل الصفوف (RLS). أكثر أمانًا واستقرارًا للتشغيل الدائم.
- **المسار (ب) — مبسّط (الأسرع):** وضع التطوير بدور واحد. أسهل، لكنه أبطأ وغير مخصّص للإنتاج.

---

## 0) المتطلبات

- **Node.js 20+** (مُختبَر على 22).
- **PostgreSQL 16** — الأسهل عبر **Docker** (مضمّن في `docker-compose.yml`)، أو تثبيت أصلي.
- **git**، ومساحة قرص ~1GB.

تحقّق:

```bash
node -v        # يجب أن يكون 20 أو أحدث
docker -v      # إن كنت ستستخدم Docker لقاعدة البيانات
```

## 2) قاعدة البيانات (PostgreSQL 16)

### عبر Docker (موصى)

```bash
docker compose up -d
```

يُشغّل هذا PostgreSQL على المنفذ **5433** بالمستخدم المالك `audit` وكلمة المرور `audit` وقاعدة `audit_dashboard`.

> إن كان 5433 مشغولًا، غيّر الرقم الأيسر في `docker-compose.yml` وحدّث الروابط في `.env`.

### أو PostgreSQL مثبّت أصليًا

أنشئ قاعدة `audit_dashboard` ومستخدمًا مالكًا، وعدّل الروابط في `.env` وفق مضيفك ومنفذك.

## 3) ملف البيئة `.env`

```bash
cp .env.example .env
```

ثم عدّله. **ولّد كلمات المرور والمفتاح السري أولًا:**

```bash
openssl rand -base64 48   # AUTH_SECRET
openssl rand -base64 24   # كلمة مرور audit_app
openssl rand -base64 24   # كلمة مرور audit_dispatch
```

### للمسار (أ) الإنتاجي

```dotenv
# التشغيل: الدور غير المالك audit_app (خاضع لعزل الصفوف RLS)
DATABASE_URL="postgresql://audit_app:APP_PASSWORD@localhost:5433/audit_dashboard?schema=public"

# الترحيلات/التزويد: المالك (يتجاوز RLS) — مع docker-compose المالك هو audit:audit
DIRECT_DATABASE_URL="postgresql://audit:audit@localhost:5433/audit_dashboard?schema=public"

# المُشغّل الخلفي: الدور المحدِّد فقط audit_dispatch
DISPATCH_DATABASE_URL="postgresql://audit_dispatch:DISPATCH_PASSWORD@localhost:5433/audit_dashboard?schema=public"

# المصادقة — إلزامية في الإنتاج
AUTH_SECRET="<الناتج من openssl rand -base64 48>"
AUTH_REQUIRED="true"

# منشأ إضافي مسموح للطلبات من أجهزة أخرى (IP الخادم + المنفذ):
ALLOWED_ORIGINS="http://192.168.1.50:3000"

# حفظ الملفات المصدرية — مسار دائم مطلق (ليس /tmp) في الإنتاج
STORAGE_PROVIDER="local-fs"
STORAGE_LOCAL_DIR="/var/lib/sarat/object-store"

# اختياري: تحليل المستندات الحقيقي عبر Claude OCR (بدونه يُستخدم محلّل بديل)
ANTHROPIC_API_KEY=""
```

> استبدل `192.168.1.50` بعنوان IP الفعلي لخادمك، و`APP_PASSWORD`/`DISPATCH_PASSWORD` بالقيم التي ولّدتها.
> أنشئ مجلّد الحفظ وامنحه الصلاحية: `sudo mkdir -p /var/lib/sarat/object-store && sudo chown $USER /var/lib/sarat/object-store`

### للمسار (ب) المبسّط

اجعل الروابط الثلاثة تشير كلها إلى المالك، واترك المصادقة اختيارية:

```dotenv
DATABASE_URL="postgresql://audit:audit@localhost:5433/audit_dashboard?schema=public"
DIRECT_DATABASE_URL="postgresql://audit:audit@localhost:5433/audit_dashboard?schema=public"
DISPATCH_DATABASE_URL="postgresql://audit:audit@localhost:5433/audit_dashboard?schema=public"
AUTH_SECRET="<الناتج من openssl rand -base64 48>"
AUTH_REQUIRED="true"
STORAGE_PROVIDER="local-fs"
STORAGE_LOCAL_DIR="/var/lib/sarat/object-store"
```

## 4) تجهيز قاعدة البيانات

```bash
npm run prisma:generate
npx prisma migrate deploy      # يطبّق الترحيلات عبر DIRECT (المالك) وينشئ الأدوار
```

### تفعيل دخول الأدوار (المسار أ فقط)

الأدوار `audit_app` و`audit_dispatch` تُنشأ بلا صلاحية دخول. فعّلها بنفس كلمات المرور التي وضعتها في `.env`:

```bash
docker exec -it audit_dashboard_db psql -U audit -d audit_dashboard
```

داخل psql:

```sql
ALTER ROLE audit_app      LOGIN PASSWORD 'APP_PASSWORD';
ALTER ROLE audit_dispatch LOGIN PASSWORD 'DISPATCH_PASSWORD';
\q
```

### زرع الحسابات الأولية

النظام يحتاج حساب دخول واحد على الأقل. الـseed ينشئ مكتبًا ومستخدمين تجريبيين:

```bash
# يُشغَّل بدور المالك (إدراج المكتب الأول يتجاوز RLS)
DATABASE_URL="$DIRECT_DATABASE_URL" npm run prisma:seed
```

يُنشئ حسابات مثل `partner@almeezan.sa` / `senior@almeezan.sa` بكلمة المرور `Audit@1234`.
**غيّر كلمات المرور هذه فورًا** في بيئة حقيقية.

## 5) التشغيل

### المسار (أ) الإنتاجي

```bash
npm run build
npx next start -H 0.0.0.0 -p 3000        # -H 0.0.0.0 ليُتاح من أجهزة الشبكة
```

وفي عملية/طرفية ثانية، شغّل المُشغّل الخلفي (ضروري لتنفيذ عمليات التدقيق G4):

```bash
npm run dispatch
```

### المسار (ب) المبسّط

```bash
npx next dev -H 0.0.0.0 -p 3000
# وفي طرفية ثانية:
npm run dispatch
```

## 6) الوصول من جهاز آخر

1. اعرف عنوان IP للخادم: `hostname -I` (لينكس) أو `ipconfig` (ويندوز).
2. من أي جهاز في نفس الشبكة افتح: `http://<IP-الخادم>:3000`
3. افتح المنفذ في الجدار الناري على الخادم:

```bash
# لينكس (ufw)
sudo ufw allow 3000/tcp
```

> تأكّد أن `ALLOWED_ORIGINS` في `.env` يحتوي على نفس العنوان الذي تستخدمه في المتصفح (بروتوكول + IP + منفذ).

---

## 7) إبقاء النظام يعمل دائمًا (اختياري)

### عبر PM2

```bash
npm i -g pm2
pm2 start "npx next start -H 0.0.0.0 -p 3000" --name sarat-web
pm2 start "npm run dispatch" --name sarat-dispatch
pm2 save
pm2 startup     # يفعّل الإقلاع التلقائي مع الخادم
```

- تحديث لاحق: `git pull` ← `npm install` ← `npm run build` ← `pm2 restart all`.
- قاعدة البيانات (Docker) تبقى تعمل تلقائيًا بفضل `restart: unless-stopped`.

## 8) التحقّق والصيانة

- **تحقّق الصحة:** افتح `http://<IP>:3000` وسجّل الدخول.
- **النسخ الاحتياطي لقاعدة البيانات:**
  ```bash
  docker exec audit_dashboard_db pg_dump -U audit audit_dashboard > backup_$(date +%F).sql
  ```
- **سجلّات:** `pm2 logs sarat-web` / `pm2 logs sarat-dispatch`.

## ملاحظات مهمة

- **الإنتاج يفرض المصادقة دائمًا** ويرفض المفتاح السري القصير أو القيم الافتراضية — استخدم `AUTH_SECRET` عشوائيًا طويلًا (≥ 32 حرفًا).
- **التشغيل الإنتاجي يجب أن يكون بدور `audit_app`** (غير المالك)؛ تشغيله بالمالك يفشل بفحص RLS الوقائي.
- **`STORAGE_LOCAL_DIR`** يجب أن يكون مسارًا دائمًا (وحدة تخزين مثبّتة)، وليس تحت `/tmp` في الإنتاج.
- **المُشغّل الخلفي `npm run dispatch`** يجب أن يعمل بجانب الواجهة، وإلا لن تُنفَّذ عمليات التدقيق G4 (ستبقى في الانتظار).
- **الأمان:** لا تعرّض المنفذ للإنترنت مباشرةً دون وسيط عكسي (Nginx/Caddy) وشهادة TLS؛ داخل الشبكة المنزلية الوصول عبر IP كافٍ.
